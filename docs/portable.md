# 可搬迁性

> 本文为参考资料，规则本体见 [`scope.md`](./scope.md) §1（P2）。

---

## 1. 唯一的要求

把 bin 所在文件夹整个移动到其它路径（或其它机器），应用仍能打开，数据仍在。

要求只有这一条。不必证明"没写到别处"，也不必重定向任何 webview / GTK / fontconfig /
shader cache 的写入：那些全部豁免（`scope.md` §1.1）。

## 2. 它实际要求的三件事

| # | 要求 | 为什么 |
|---|---|---|
| 1 | 数据目录相对可执行文件推导，不由 `$HOME` / `%APPDATA%` 推导 | 这是"文件移动后数据跟着走"的全部含义 |
| 2 | 库里不存绝对路径 | 存了绝对路径，迁移后它们全部失效；失效是静默的，因为外键指向不存在的位置 |
| 3 | 不可写时明确报错，不静默退回 OS 目录 | 否则用户以为数据在 U 盘上、实际在本地磁盘；用户拔下 U 盘，数据没了，而用户不知道 |

第 2 条最容易被忽略，因为它体现在数据模型里，不在目录结构上。凡是"文件位置"性质的
东西都应该存相对标识或直接存进库本身。密钥本来就存在库里，因此这条天然满足，但要守住：
不得引入"密钥文件路径"字段。

## 3. 数据目录放哪（平台差异）

| 平台 | "bin 所在文件夹" 实际是 | 注意 |
|---|---|---|
| Linux | 二进制所在目录 | 装到 `/usr/bin` 时那里没有数据目录，退回 OS 目录。目录存在但不可写是另一回事：拒绝启动（§4 第 3 条） |
| Windows | `.exe` 所在目录 | 装到 `Program Files` 时同上：默认无数据目录，退回 OS 目录 |
| macOS | `.app` 旁边的目录 | ⚠️ `.app` 内部不可写：写入会破坏代码签名 |

### 3.1 数据目录里放什么

| 文件 | 作用 |
|---|---|
| `config.json` | 用户配置。只有 `close_behavior`（`tray` / `exit`；plan 0303） |
| `akasha.db` | 加密库（ADR-0002 D1）：主机 / 密钥 / 串口 / 转发规则四类池，另加 known_hosts 缓存（ADR-0003 D11，plan 0503 起；格式 `user_version = 2`） |

⚠️ 库带格式版本：v1 的库在新版本程序中打开时会被自动升级到当前格式（plan 0503）；
升级之后旧版本程序无法打开该库（`UnsupportedVersion`）。迁移的对象是文件本身，
因此目标机器上的程序版本不得低于来源机器。

数据目录名 `akasha-data/`，判定逻辑写在 `src-tauri/src/config.rs`：目录本身就是"要便携"
的标记，存在就用它，不存在才退回 OS 目录。⚠️ 该目录不会被自动创建。开发构建的 bin 目录
是可写的，自动创建会在用户未要求时替其选择便携模式。

## 4. 触发方式：由标记决定，不无条件

1. bin 同目录存在数据目录 `akasha-data/` → 用它。该目录本身就是标记，不存在第二个标记文件。
2. 否则 → 退回 OS 标准数据目录。
3. 便携模式下若检测到不可写 → **启动即明确报错**。

第 3 条与"退回"是两个独立分支，不得合并：只在用户没有要求便携时才退回；用户明确要求
便携却做不到时必须报错，不得替用户决定。

> 便携目录不可写时，app 在启动路径上拒绝启动（plan 0405），
> 打一条 `portable data dir not writable`（含 OS 自己的错误原文），并以退出码 `2` 退出，
> 不静默退回 OS 目录。判"可写"的方式是真的写一个探针文件再删掉，因为 mode 位看不出
> ACL / 只读挂载 / squashfs。
> ⚠️ 已知边界：错误呈现只有日志与非零退出码，没有弹窗；从桌面菜单启动的用户看不到
> stdout。GUI 上的错误呈现属于真实 UI 阶段。

## 5. 怎么验证

验证方式：执行下面五步。

```
1. 正常启动一次，确认数据落在 bin 同目录（而非 ~/.local/share 之类）
2. 完全退出
3. 把整个文件夹移动到另一个路径（同机换目录即可，跨机器是同一回事）
4. 从新位置启动
5. 断言：能开，且原有的主机/密钥/转发规则都在
```

第 5 步是关键：除了"能开"，还要验证数据仍在且可用。迁移后能开但规则全丢也算失败，
这是存了绝对路径的典型症状。

`just portable` 执行这五步（plan 0405），全部自动：第 2 步由用例回收进程，无需人工触发。
判据见 `src-tauri/tests/portable.rs`：

* 它把可执行文件复制进临时布局（`<tmp>/akasha-portable-<pid>-a/`），因为被测的是
  "数据目录从 bin 所在目录推导"，而构建目录无法移动；
* 用 app 自己的命令（`vault_status` / `vault_unlock`）与 `lifecycle` probe 观察它挑了哪个
  数据目录，不靠 grep 日志反推；
* 移动到 B 后再启动一次，断言四类池各读回一行，并用库函数逐项比对内容，只比对行数不够；
* ⚠️ 它不能与其它 akasha 实例同时运行：单实例会让第二份自己退掉。配方会先查一遍。
