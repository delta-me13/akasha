# 可搬迁性

> 本文是**参考资料**，不是规则。约束本身在 [`scope.md`](./scope.md) §1（P2）。
>
> ⚠️ **本文已大幅缩减**（2026-09-11）。原版本试图论证"零外部写入"，
> 引来一整套环境变量重定向与启动时序约束。用户明确豁免 webview 及其依赖栈后，
> **判据从"没有写到别处"简化为"搬走文件夹后还能开"** —— 后者便宜得多，
> 且与本项目的实际诉求一致。被删掉的内容不是"推迟"，是**不必要**。

---

## 1. 唯一的要求

**把 bin 所在文件夹整个移动到别的路径（或别的机器），应用照样能开，数据还在。**

就这一条。不需要证明"没写到别处"，不需要重定向任何 webview / GTK / fontconfig /
shader cache 的写入 —— 那些**全部豁免**（`scope.md` §1.1）。

## 2. 它实际要求的三件事

| # | 要求 | 为什么 |
|---|---|---|
| 1 | **数据目录相对可执行文件推导**，而不是从 `$HOME` / `%APPDATA%` 推导 | 这是"文件搬走了数据跟着走"的全部含义 |
| 2 | **库里不存绝对路径** | 存了绝对路径，搬家后它们全部失效 —— 而失效是**静默的**（外键指向不存在的位置） |
| 3 | 不可写时**明确报错**，不静默退回 OS 目录 | 否则用户以为数据在 U 盘上、实际在本地磁盘；他拔了 U 盘，数据没了，而他不知道 |

第 2 条最容易被忽略：它不体现在目录结构上，而体现在**数据模型**里。
凡是"文件位置"性质的东西都应该存**相对标识或干脆存进库本身**（我们本来就把密钥
存在库里，所以这条天然满足 —— 但要守住，别哪天引入一个"密钥文件路径"字段）。

## 3. 数据目录放哪（平台差异）

| 平台 | "bin 所在文件夹" 实际是 | 注意 |
|---|---|---|
| Linux | 二进制所在目录 | 装到 `/usr/bin` 时不可写 → 退回 OS 目录 |
| Windows | `.exe` 所在目录 | 装到 `Program Files` 时不可写 → 退回 OS 目录 |
| macOS | **`.app` 旁边的目录** | ⚠️ **`.app` 内部不可写**：会破坏代码签名 |

## 4. 触发方式：由标记决定，不无条件

1. bin 同目录存在数据目录（或便携标记文件）→ 用它
2. 否则 → 退回 OS 标准数据目录
3. 便携模式下若检测到**不可写** → **启动即明确报错**

> 第 3 条与"退回"是两件事，不要合并：**只在用户没要求便携时才退回**，
> 用户明确要了便携却做不到时，必须报错而不是替他决定。

## 5. 怎么验证

比原版本简单得多 —— **直接做那个动作**：

```
1. 正常启动一次，确认数据落在 bin 同目录（而非 ~/.local/share 之类）
2. 完全退出
3. 把整个文件夹移动到另一个路径（同机换目录即可，跨机器是同一回事）
4. 从新位置启动
5. 断言：能开，且原有的主机/密钥/转发规则都在
```

第 5 步是关键：**只验证"能开"不够**，要验证**数据还在且可用** ——
搬家后能开但规则全丢，也算失败（那正是"存了绝对路径"的典型症状）。

**目标形态**（**尚未实现**）：把它做成一条配方，形态类似 `just syscheck`，
其中第 1 步与第 3–5 步是自动的，第 2 步需要人工触发（或由配方结束进程）。

## 6. 曾经考虑过、现已不需要的

留档以免重新论证：

| 曾考虑的机制 | 为什么不需要了 |
|---|---|
| 重定向 `XDG_*` / `WEBVIEW2_USER_DATA_FOLDER` / `CFFIXED_USER_HOME` | webview 依赖栈的写入已豁免，重定向没有受益方 |
| "环境变量必须早于 GTK/AppKit 初始化"的时序约束 | 同上。没有重定向就没有时序问题 |
| `strace` / Process Monitor / `fs_usage` 全量审计 | 判据不再是"零外部写入"，全量审计失去意义 |
