# 文档语体：禁用语表与维护方法

规则本体在 [`AGENTS.md`](../AGENTS.md) §8.2（禁止哪些写法、术语怎么对照、哪些东西
不得为"书面化"而改动）。本文件只回答两个问题：**禁用语表在哪、怎么加一条**。
它是 `just docs-style` 的**唯一数据源** —— 改表即改门禁，不需要动 `justfile`。

## 1. 表怎么被使用

`just docs-style` 对 `AGENTS.md`、`CLAUDE.md`、`README.md`、`ROADMAP.md` 与
`docs/**/*.md` 逐份检查：**先剥掉围栏代码块与行内代码**，再用下表拼成的正则做一次
`grep -E`；命中即失败，并打印文件名与行号。

非快速失败：逐份文档各查一遍，**全部查完才汇总报错**（不在第一份命中的文档处终止），
因此一轮即可看到全部待改位置；单份文档命中超过 20 条时列出前 20 条，并写明未列出的条数。

拼装规则：取下面两个标记**之间**的围栏块，

- **每行一个 POSIX ERE 片段**；所有片段用 `|` 拼成一条正则；
- `#` 开头的行是分组注释，空行与围栏行被忽略；
- 因此**片段自身不得含 `|`** —— 需要"或"就多写几行；
- 标记之外的内容（本节说明、§2 的步骤、§3 的候选表）不参与拼装。

## 2. 人工加一条禁用语的步骤

1. **先判断它能否机械判定。** 表里的片段是直接匹配的裸文本，所以只收"出现即缺陷"的词。
   需要上下文才能判定的（见 §3）**不要进表**，留给人工审阅。
2. **在对应分组里加一行**（组内按词义归类，不排序）。若新条目是某个术语的口语写法，
   同时在 `AGENTS.md` §8.2 的术语对照表里补一行 —— 那里回答"该写成什么"，表只回答
   "什么不许出现"。
3. **执行 `just docs-style`。** 新条目在全仓必须**零命中**：有命中就先改文档；
   若命中的是正当用法（如命令输出原文、协议术语），说明片段写得过宽，回到第 1 步收窄。
4. **用诱饵验证一次。** 提交前确认片段不会误伤邻近词：在任意文档里临时写一个合法词
   （如 `预览器`、`漏洞`），确认门禁不报它，再把这段临时内容删掉 —— 只测"命中"分不清
   "规则在工作"与"规则范围写歪了"。
5. **同步文档说明。** 若这次改动改变了 AGENTS.md §8.2 的口径（新增一类禁止写法，
   而不只是补一个词），在 §8.2 的表里加一行；只补同义词则不需要动 §8.2。
6. **提交。**

## 3. 为什么不把某些词放进来

| 候选 | 为什么不能按裸词匹配 | 需要收窄时怎么写 |
|---|---|---|
| `别` | `区别` / `特别` / `分别` / `类别` / `别名` 都含它 | `别把`、`别再`、`别只` 这类词组 |
| `洞` | `漏洞` 是合法词 | `门禁的洞`、`个洞` |
| `死` | `死锁` / `死循环` 是标准术语 | `死掉`、`搞死` 这类词组 |
| `红` / `绿` | 可能出现在配色、转义序列等正当语境 | 不进表，人工判断 |
| `打` | `打印` / `打补丁` 与 `打出来` 的词义不同 | 完整词组，如 `打出来` |

## 4. 维护纪律

- **表和规则不许分家**：本文件只列"不许出现的字面"，判断标准仍在 `AGENTS.md` §8.2。
  两者冲突时以 §8.2 为准，并回来修表。
- **一次只加一类**：新增片段后立刻执行一次门禁，把"新条目误伤"与"文档里确有该写法"
  分开处理，不要攒着一起改。
- **不要为了转绿而删条目**：命中意味着要么改文档、要么收窄片段；直接删片段等于把门禁
  调松，而这类改动不会留下任何痕迹。
