# Plan 0503: known_hosts 校验与缓存

- **关联**：ROADMAP 阶段 5 ·「known_hosts 校验与缓存」
- **前置**：plan 0502（连接建立路径已存在）
- **状态**：未规划（骨架）
- **展开时机**：**立即** —— plan 0502 已完成；本 plan 排在 SSH 接进前端（0504）之前，
  因为"未知 host key 怎么办"是**接口形状**（谁问、问什么、答案存在哪），
  先定它，0504 才只需把问题送到前端，不必自造一套临时信任

## 目标

host key 校验 + 结果缓存进库，避免每次连接重新确认（`scope.md` §2.2 的"内存凭据缓存"表）。

**安全判据不可协商**：host key 变化时必须**拒绝连接并提示**，绝不静默接受 ——
静默接受等于把中间人攻击变成默认行为。

## 非目标

- 复用系统 `~/.ssh/known_hosts` 的完整语义（哈希主机名、`@cert-authority` 等）：
  需要哪些形态在展开时定，不要顺手全实现
- 凭据（私钥 / 口令）的缓存 —— 那是 plan 0502 的职责，两者不要混在一个缓存里

## 判据（来自 ROADMAP，展开时必须变成可粘贴的验收命令）

host key 变化时**拒绝连接并提示**（不静默接受）。

## 展开时要补

- [ ] 「## 步骤」：首次连接（未知 host）的交互形态 —— 拒绝？询问？这是**产品决定**，必须先定
- [ ] 「## 验收命令」：怎么稳定复现"host key 变化"（换密钥重启测试 sshd 容器是常见做法）
- [ ] 缓存表结构与"清除某主机指纹"的操作（用户会需要，且它属于凭据池的邻居）
