# Plan 0904: 离线缓存（fingerprint 自检 / revisionDate 刷新）

- **关联**：ROADMAP 阶段 9 ·「离线缓存：**私钥离线自检用 `fingerprint`**，联网刷新用 `revisionDate`」
- **前置**：plan 0903（导入路径已存在）
- **状态**：未规划（骨架）
- **展开时机**：只读导入稳定之后

## 目标

加密离线缓存，**静态保护强度与本地池同级**（`scope.md` §7）。

两类元数据的职责必须分开（结论与推导见 [`../bitwarden.md`](../bitwarden.md)）：

- **`fingerprint`**：私钥的**离线自检**能力（断网也能校验缓存完整性）
- **`revisionDate`**：**联网刷新**的判据（变化即提示刷新）

> 混用两者是本节最易犯的错误：`fingerprint` 不能用于判断"上游是否有更新"。

## 非目标

- 在本地实现 vault 密码学（`no`）
- 自动后台轮询刷新（先做"用户触发的刷新提示"）

## 判据（来自 ROADMAP，展开时必须变成可粘贴的验收命令）

**断网时能校验缓存完整性**；**联网且 `revisionDate` 变化时提示刷新**。

## 展开时要补

- [ ] 「## 步骤」：缓存文件的落点与加密方式（复用 plan 0402 的密钥体系还是独立口令，须先确定）
- [ ] 「## 验收命令」：断网场景如何稳定复现；`revisionDate` 变化如何构造
- [ ] 缓存失效与清理策略（用户删条目 / 变体切换 / 缓存损坏时的行为）
