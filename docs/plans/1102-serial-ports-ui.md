# Plan 1102: 端口枚举与参数接进界面

- **关联**：ROADMAP 阶段 11 ·「端口枚举与参数接进界面（列端口 + 手动路径兜底 + 池行取值 + 可读报错）」
- **前置**：plan 1101（会话能打开）· plan 0802（`ports()` 与 `TryFrom<u8>` 已就位）
- **状态**：未规划（骨架）
- **展开时机**：plan 1101 之后

## 目标

界面上能看到本机端口，挑一条或手动输入路径，并按池行的参数打开；
取值不合法时当场看到**字段与取值**。

## 非目标

- 会话的打开 / 关闭与回收（plan 1101）；设备消失（plan 1103）
- 热插拔事件驱动的列表刷新（先手动刷新）
- 串口配置池的增删改查界面（与主机池的界面缺口同一批，尚未规划）

## 1101 留下的接口（展开时直接用，不要另开一条命令）

- `open_serial_session(channel, params)` 收的是**六个字段**（`SerialParams`），不是池行 id ——
  所以"手输路径 + 参数可编辑"与"从池里挑一行"**共用同一条命令**（1101 的 `SerialPicker`
  已经走的是后者：把池行原样填进 `params`）。
- **越界取值已经在后端报字段与取值**（`SerialIpcError::Settings` 的 `field` / `value`）——
  1102 要做的是把它**显示出来**（`SerialInvokeError.settingsProblem`），不是再写一份校验。
- 打开一个设备**不碰库**，所以手输路径那条路**不需要解锁**（只有列池里有哪些需要）。

## 判据（来自 ROADMAP，展开时必须变成可粘贴的验收命令）

界面上看到本机枚举结果并据此（或手输路径）打开；取值越界时显示字段与取值。
