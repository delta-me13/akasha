# Plan 0403: 四套池的 CRUD

- **关联**：ROADMAP 阶段 4 ·「四套池的 CRUD：密钥 / ssh 配置 / serial 配置 / 端口转发规则」
- **前置**：plan 0401（库能开）· plan 0402（密钥能派生）
- **状态**：未规划（骨架）
- **展开时机**：库与密钥路径打通之后

## 目标

四套独立池的增删改查：**密钥池**（本地）/ **ssh 配置池** / **serial 配置池** / **端口转发规则池**
（字段集见 `scope.md` §3 的表）。库是**唯一真相源**，不是缓存。

## 非目标

- UI（各池的呈现形式未定，后端先按语义建模，见 `scope.md` §1.2）
- 从系统 `~/.ssh/config` 导入（阶段 5 的 plan 0504）
- Bitwarden 导入池（阶段 9）
- ~~配置文件的迁移~~ → **已裁定不做**：`config.json` **不并进库里**（[ADR-0002](../adr/0002-secret-storage.md) D11）——
  关窗行为必须在**解锁之前**就可用，而加密库里的东西解锁前读不到

## 判据（来自 ROADMAP，展开时必须变成可粘贴的验收命令）

- 各自的 **round-trip 单测**通过（写入 → 读出 → 字段一致）
- **库里不存绝对路径**（P2，`portable.md` §2 第 2 条）

## 展开时要补

- [ ] 「## 步骤」：按池逐个落地，每池一个可独立验证的小步
- [ ] 「## 验收命令」：round-trip 单测 + 一条"库里没有绝对路径"的检查
- [ ] 确认 `config.json` 与库文件在**同一个数据目录**（库的落点由 ADR-0002 D1 定）；
      **不并入库** —— 这一条曾写作"此时应并入"，已被 D11 推翻
