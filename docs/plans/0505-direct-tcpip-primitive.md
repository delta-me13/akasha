# Plan 0505: `direct-tcpip` 原语

- **关联**：ROADMAP 阶段 5 ·「`direct-tcpip` 原语（本阶段先用于跳板）」
- **前置**：plan 0502（能连上、能认证）· plan 0504（**已完成** —— 真 app 上能开 SSH 会话了）
- **状态**：未规划（骨架）
- **展开时机**：plan 0504 之后 —— 原语的消费者（跳板 / 端口转发 / SFTP）都要先有一条
  "从 app 打开、看得见"的 SSH 会话才验得了。✅ 这个前提现在成立了
- **接口归属（0504 的结论，别两边各定一套）**：`Handle` 仍归 **`SshTransport` 自己**
  （它把句柄交给那条 `pump` task，收尾的唯一出口在那里）；0504 **没有**改这一点。
  原语要拿句柄，只有两条路：由 `SshTransport` 暴露一条**受控的借用口**，
  或者跳板那条路**自己持有连接**（`connect_stream` 直接吃一条 `AsyncRead + AsyncWrite`）

## 目标

实现一次 `direct-tcpip` channel 链式串接，落在 `src-tauri/crates/akasha-ssh`，**供三处复用**：

1. **跳板 / ProxyJump**（本阶段）
2. SFTP host↔host 的 **B 档**（阶段 7）
3. **SSH 本地转发**（阶段 6）

先做跳板 = 顺手拿到另外两处的地基（`scope.md` §2.2）。

## 非目标

- **远程转发（`-R`）不在本原语范围内**：那是另一套机制（服务端发起 `forwarded-tcpip`），
  别把它和本地转发混为一谈
- 隧道实体的状态机（plan 0601）：本 plan 只做原语，不做生命周期

## 判据（来自 ROADMAP，展开时必须变成可粘贴的验收命令）

ProxyJump 可连通**只对跳板机可见**的目标。
