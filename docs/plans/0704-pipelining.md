# Plan 0704: 并发 in-flight 请求（pipelining）

- **关联**：ROADMAP 阶段 7 ·「并发 in-flight 请求（pipelining）」
- **前置**：plan 0702（传输引擎，含落盘不变量）
- **状态**：未规划（骨架）
- **展开时机**：传输引擎可用、落盘不变量已验过之后

## 目标

传输引擎支持**并发 in-flight 请求**：多个小文件的往返开销主导耗时，
串行请求无法靠拓扑优化弥补（`scope.md` §4.1）。

并发度要有**上限**（可配置，有默认值），并且**不能破坏 plan 0702 的落盘不变量**。

## 非目标

- 多路复用 SFTP 通道的选择（沿用阶段 5 的连接模型：一 Session 一连接）
- 断点续传、限速、队列优先级（都不是 v1）

## 判据（来自 ROADMAP，展开时必须变成可粘贴的验收命令）

**大量小文件**的吞吐**显著优于**串行请求。

## 展开时要补

- [ ] 「## 步骤」：并发模型（任务池 / 信号量）与失败传播（一个文件失败是否中止整批）
- [ ] 「## 验收命令」：可量化的对比 —— 同一批小文件串行 vs 并发的实测耗时（写出数字口径）
- [ ] 失败与取消时的临时文件清理在并发下仍然正确（并发下最易遗漏的一点）
