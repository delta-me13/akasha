# Plan 1103: 设备消失时串口会话以可读原因结束

- **关联**：ROADMAP 阶段 11 ·「设备消失时串口会话以可读原因结束，标签页随之关闭」
- **前置**：plan 1101（会话能打开、能回收）
- **状态**：未规划（骨架）
- **展开时机**：plan 1101 之后（可与 plan 1102 并行）

## 目标

串口被拔掉（或对端消失）时这条会话**自己结束** —— 与 local / ssh 的第三条回收路径同形：
回收它自己 + 关闭那个标签页，且原因可读。

## 非目标

- 自动重连与热插拔事件（`scope.md` §10，`later`）—— 这一条只保证"结束得干净、看得见"
- 设备回来之后怎么接（重新打开是一条新会话）

## 判据（来自 ROADMAP，展开时必须变成可粘贴的验收命令）

把测试用的 PTY 主端关闭（等价于拔掉设备）时会话结束、没有残留注册。

## 1101 已经留下的部分（本条只补"原因可读"）

- 「会话自己结束」这条路径**形状上已经通了**（plan 1101 没有为它改一行）：设备消失 → 读端报错 →
  输出流结束 → `retire` → `session_ended` → 标签页随之关闭。所以本条的对象是
  **那句话说不说得出来**（串口没有退出码，`session_ended` 的 `status` 因此是 `null`），
  以及"没有残留注册"这条断言本身。
- 判据里"没有残留注册"的读数口是 `app_state { probe: "sessions" }`（串口没有本地进程）。
