# Plan 0307: macOS 上从 Dock 唤回窗口

- **关联**：ROADMAP 阶段 3 ·「macOS 上从 Dock 唤回窗口」
- **前置**：plan 0301 / 0302（托盘与「隐藏而非销毁」）；本条要先有一次实测
- **状态**：未规划（骨架）
- **展开时机**：实测确认缺口之后；若托盘与 Dock 的语义要一起改，先写 ADR

## 目标

macOS 上窗口被收进托盘（隐藏）之后，**点 Dock 图标能把窗口唤回来**。

今天的现状是静态读代码得出的：全仓只处理 `RunEvent::Exit` 与 `RunEvent::Ready`
（`src-tauri/src/lib.rs`），**没有** `RunEvent::Reopen` 的处理点；而窗口隐藏之后唯一的唤回入口
是托盘子菜单的「显示/隐藏窗口」。Dock 的等价入口因此没有行为 —— 这与
`docs/scope.md` §5「关窗不退出、必须能再次唤出」的口径不一致。

## 非目标

- **不做视觉/版式工作**（`AGENTS.md` §4.0）：本 plan 只补一条唤回行为，不碰界面观感。
- **不做托盘模板图标**：`docs/scope.md` §377 已把 macOS/Linux 的图标尺寸与模板图标归 UI 阶段，
  与本条不是同一件事，不在这里顺带处理。
- **不改关闭语义**：`close_behavior` 的两个取值与它们的降级口径（托盘不可用 → 关窗即退出）不变。

## 前置（展开时先做，缺一条都不能写步骤）

1. **实测一次**：托盘可用时点 Dock 图标，窗口是否回来。判据以 app 自己的状态为准
   （`app_state { probe: "lifecycle" }` 的 `close_action`、以及窗口可见性），不得靠日志反推。
2. **确认触发条件**：窗口是「隐藏」而不是「销毁」（plan 0302）时，macOS 是否发出 `Reopen`，
   以及它是否要求「没有可见窗口」。
3. **确认与托盘菜单的分工**：两个入口都唤回同一个窗口，不新建窗口、不重置终端缓冲。

## 判据（来自 ROADMAP，展开时必须变成可粘贴的验收命令）

- 隐藏窗口之后点 Dock 图标，窗口回到前台且**仍是同一个窗口**（终端回滚缓冲与正在运行
  的子进程原样在），进程不重启、不新建实例；
- 托盘不可用（或 `close_behavior=exit`）时行为不变：前者关窗即退出，后者关窗即退出且零残留；
- Linux / Windows 上无变化。
