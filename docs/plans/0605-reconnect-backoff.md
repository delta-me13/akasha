# Plan 0605: 断线重连（3 次 + 指数退避）

- **关联**：ROADMAP 阶段 6 ·「断线重连：**3 次 + 指数退避**，然后标记失败」
- **前置**：plan 0601（状态机）· 至少一种转发已能工作（plan 0602）
- **状态**：未规划（骨架）
- **展开时机**：本地转发跑通、状态机可观测之后

## 目标

**有限次**重连（默认 3 次，指数退避；参数可配置但有默认值）→ 放弃 → 标记 `失败`。
不做无限重连（避免后台无谓重试与惊扰防火墙，`scope.md` §2.2）。

⚠️ **"标记失败"必须可见**：否则就是最危险的失败模式 —— 用户以为隧道还在转发，
实际早已死掉，直到某天发现连不通才察觉。落点是托盘菜单（`scope.md` §5.2）。

## 非目标

- 无限重连 / 保活探测调优（`later`）
- 关闭 Session 时中止重连循环（plan 0606）—— 但本 plan 必须**预留**那个中止入口

## 判据（来自 ROADMAP，展开时必须变成可粘贴的验收命令）

拔网线后进入「重连中」，耗尽次数后变「失败」**且托盘可见**；**可手动重试**。

## 展开时要补

- [ ] 「## 步骤」：退避序列的具体取值（从 ADR-0003 抄）；`重连中(第 n 次)` 的 n 怎么上报
- [ ] 「## 验收命令」：怎么稳定复现断线（iptables / 关掉测试 sshd 容器 / 拔网线）
- [ ] 手动重试的入口与状态复位（`失败` → `连接中` 的合法转移）
