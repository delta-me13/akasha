# 架构决策记录（ADR）

终端项目的选型坑多，且容易被反复推翻。任何**不可轻易撤销**的决定都要在这里留痕
（见 `AGENTS.md` §8）。

约定：文件名 `NNNN-<slug>.md`，编号连续不重用；ADR 一经接受不再修改，
只追加"被 NNNN 取代"。

---

## 写 ADR 的门槛：两条**都**满足才写

**现在还没开工，所以 ADR 要少。** 一条 ADR 必须同时满足：

1. **不可逆** —— 改了要迁移用户数据、改线协议、或重写一层；不是改个配置就行
2. **会被反复推翻** —— 后人（或未来的自己）一定会问"为什么不用 X"

只满足一条的，写进 [`../scope.md`](../scope.md) 的"已定案"就够。
**决定本身不会丢**（scope.md 是能力的唯一来源），所以不必为了"记得住"而写 ADR。

> - 反面例子：把"点叉默认收托盘"写成 ADR —— 它是可逆的配置项，scope.md 足够。
> - 正面例子：SQLCipher + 口令派生 —— 它决定**数据文件格式**，改它要迁移用户数据。
