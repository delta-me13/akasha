# 文档索引

原则：**先读索引，再按需深入**（渐进披露）。每件事只有一处真相 ——
不要把 `AGENTS.md` 的内容抄到这里，也不要把进度写回 `AGENTS.md`。

| 文件 | 回答什么问题 | 时效性 | 什么时候读 |
|---|---|---|---|
| [`../AGENTS.md`](../AGENTS.md) | **规则**：什么能做/不能做、命令入口、工具分工 | 几乎不变（<200 行） | 每次开工前 |
| [`scope.md`](./scope.md) | **这个产品预备有什么**：能力清单、非目标、已识别风险 | 偶尔变（只增删能力条目） | 怀疑某功能"是不是我们该做的"时 |
| [`../ROADMAP.md`](../ROADMAP.md) | **我们去哪**：阶段、条目、验收标准 | 粗粒度，偶尔变 | 决定"下一步做什么"时 |
| [`STATUS.md`](./STATUS.md) | **我们现在在哪**：已验证为绿 / 已知为坏 / 下一步 / 坑 | **每次会话覆盖写** | 每次会话开始和结束 |
| [`just.md`](./just.md) | **命令怎么用**：**全部配方的权威清单** + 工作流 + 排错 | 随 justfile 变 | 忘了某条命令、或命令跑不起来时 |
| [`adr/`](./adr/) | **我们决定过什么、为什么** | **不可变**，只追加"被取代" | 想推翻某个选型之前 |
| [`plans/`](./plans/) | **单个工作项怎么做**：步骤 + 验收命令 | 随实现更新 | 动手做某个条目时 |

## 三个最容易搞混的职责

- **ADR** 回答"为什么这样做"。一旦接受不再修改，只能被新 ADR 取代。
- **plan** 回答"这次怎么做"。会随实现演化，包含可粘贴执行的验收命令。
- **STATUS** 回答"现在到哪了"。是唯一的现状来源。

> 进度**不要**写进 `ROADMAP.md` 正文 —— 只在那里勾复选框；
> 也不要把待办写进 `AGENTS.md` —— 规则与状态是两种时效性，混在一起两边都会烂。

## 为什么暂时没有 `specs/`

Spec Kit / Kiro 那类"每个特性一个 `specs/NNN-slug/{spec,plan,tasks}.md`"的结构，
是为**从规格生成代码**的流程设计的。本项目只有一个 Rust+Tauri 应用，
`plans/` 里一个工作项一个文件已经覆盖同样的内容，文件数只有 1/3。

**触发条件**：当某个工作项需要一份**冻结的、可评审的契约**（例如 IPC/协议接口），
且代码与测试都要从它派生时，再引入 `specs/NNNN-slug/`。在那之前不建。

## plan 与 ADR 的编号关系

两者**各自独立编号**，用 plan 头部的 `关联：ADR-XXXX` 字段建立关系。
（不共用编号空间：一个 ADR 可能对应 0 个或多个 plan，共用编号会产生歧义。）

## 新建 plan 的骨架

```markdown
# Plan NNNN: <标题>

- 关联：ROADMAP <阶段> / ADR-XXXX
- 状态：未开始 | 进行中 | 已完成 | 放弃

## 目标 / 非目标
## 前置检查
## 步骤（每步都能独立验证）
## 验收命令（必须能直接粘贴执行，并写出预期输出）
## 回滚
## 实施记录（边做边追加）
```

**验收命令是硬要求**：写不出可执行验收命令的条目，说明还没想清楚，不许开工。
能把验收变成 `just` 配方的，就不要写成散文（散文规则不会被强制执行）。

## 交接规则

会话结束前更新 `STATUS.md`（覆盖写，不追加）：改了什么、验证命令的**实际输出**、
下一步、新踩的坑。下一个会话只读 `STATUS.md` + 相关 plan 就能接手。

## 分层约定

- 顶层只放**规则**与**方向**：`AGENTS.md`、`ROADMAP.md`。
- `docs/` 放维护者/agent 需要的过程性材料，**不放产品面向用户的文档**。
- 子目录规则确实不同时，才在该子目录放嵌套 `AGENTS.md`（就近优先）。
  每多一个文件就多一处会漂移的地方，能不建就不建。
