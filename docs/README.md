原则：**先读索引，再按需深入**（渐进披露）。每件事只有一处真相 ——
不要把 `AGENTS.md` 的内容抄到这里，也不要把进度写回 `AGENTS.md`。

| 文件 | 回答什么问题 | 时效性 | 什么时候读 |

| [`scope.md`](./scope.md) | **这个产品预备有什么**：能力清单、非目标、已识别风险 | 偶尔变（只增删能力条目） | 怀疑某功能"是不是我们该做的"时 |

## 三个最容易混淆的职责

- **ADR** 回答"为什么这样做"。三态：**提议中**可随意改；**实现中**可随实现反馈就地改
  （每次改记一行）；**已定案**不可改，只能被新 ADR 取代。
- **plan** 回答"这次怎么做"。会随实现演化，包含可粘贴执行的验收命令。
- **STATUS** 回答"现在到哪了"。是唯一的现状来源。

> 进度**不要**写进 `ROADMAP.md` 正文 —— 只在那里勾复选框；
> 也不要把待办写进 `AGENTS.md` —— 规则与状态是两种时效性，混在一起两边都会烂。

## 为什么暂时没有 `specs/`

Spec Kit / Kiro 那类"每个特性一个 `specs/NNN-slug/{spec,plan,tasks}.md`"的结构，
是为**从规格生成代码**的流程设计的。本项目只有一个 Rust+Tauri 应用，
`plans/` 里一个工作项一个文件已经覆盖同样的内容，文件数只有 1/3。

**触发条件**：当某个工作项需要一份**冻结的、可评审的契约**（例如 IPC/协议接口），
且代码与测试都要从它派生时，再引入 `specs/NNNN-slug/`。在那之前不建。

## plan 的编号、骨架与归档

**全部在 [`plans/README.md`](./plans/README.md)**（避免同一份规则写两遍而漂移）：
阶段块号 `TTxx`、索引表、单文件 ≤200 行预算、归档规则（整份移动、**永不拼接**）、
以及新建 plan 的骨架。

两条最容易违反、也最要紧的：

- **验收命令是硬要求**：写不出可执行验收命令的条目，说明还没想清楚，**不许开工**。
  能把验收变成 `just` 配方的，就不要写成散文（散文规则不会被强制执行）。
- plan 与 ADR **各自独立编号**，用 plan 头部的 `关联` 字段建立关系
  （不共用编号空间：一个 ADR 可能对应 0 个或多个 plan，共用编号会产生歧义）。

## 交接规则

会话结束前更新 `STATUS.md`（覆盖写，不追加）：改了什么、验证命令的**实际输出**、
下一步、新增的已知问题。下一个会话只读 `STATUS.md` + 相关 plan 即可接手。

## 分层约定

- 顶层只放**规则**与**方向**：`AGENTS.md`、`ROADMAP.md`。
- `docs/` 放维护者/agent 需要的过程性材料，**不放产品面向用户的文档**。
- 子目录规则确实不同时，才在该子目录放嵌套 `AGENTS.md`（就近优先）。
  每多一个文件就多一处会漂移的地方，能不建就不建。

## 汇总类文档的纪律（防实现细节泄漏）

**汇总类 = [`../ROADMAP.md`](../ROADMAP.md) / [`STATUS.md`](./STATUS.md) / [`scope.md`](./scope.md)。**
它们回答"有什么 / 到哪了 / 去哪"，**不回答"怎么做"**。

规则本体在 `AGENTS.md` §8.1；这里是**归属对照表**——想写的时候先查它该去哪。

### 归属对照表

| 想写的内容 | 它的实际类别 | 该去哪 |
|---|---|---|
| ROADMAP 的验收行里加一条命令 | 验证手段 | `plans/TTxx-*` 的「验收命令」 |
| ROADMAP 的条目里加"因为…" | 理由 | ADR；或 `scope.md` 能力条目的理由列 |
| ROADMAP 里加"先 A 再 B"、代码块 | 步骤 | `plans/TTxx-*` |
| `scope.md` 里展开某协议的字段 / 条款 / API 全貌 | 参考资料 | 单独文档（如 `portable.md`），scope.md 留结论 + 指针 |
| `STATUS.md` 里写"第一步先做什么" | 步骤 | plan；STATUS 只写"现在在哪 + 下一步是哪个条目" |
| 汇总文档里写排错步骤 | 参考资料 | [`just.md`](./just.md) §6、[`portable.md`](./portable.md)，或专门文档 |
| CI 为什么只有一份 GitHub 工作流、为什么不再做别的 forge 的兼容层 | 规则 + 已放弃方案的成本 | [`AGENTS.md`](../AGENTS.md) §12（规则）+ [`plans/0102`](./plans/0102-ci-platform-matrix.md) 的「放弃记录」（理由与那份约束清单） |
| IPC 字节通道为什么必须走 raw、为什么生成层有一处手写 | 规则 + 已知问题 | [`AGENTS.md`](../AGENTS.md) §3.2 / §5（规则）+ [`plans/0202`](./plans/archive/0202-ipc-binary-channel.md) 的实施记录（`Channel<Vec<u8>>` 为什么是错的）+ `STATUS.md` 问题 #31 |
| 一个临时用的检查脚本 | 检查 | 做成 just 配方（[`AGENTS.md`](../AGENTS.md) §11）—— 散落的 `.sh` 不会被任何门禁照看 |
| 基准数字（MB/s、ns/批） | 会随机器变的测量结果 | [`STATUS.md`](./STATUS.md) 的「当前基线」+ 产生它的 plan 的「实施记录」。**不是门禁、不进 ROADMAP**（规则见 [`AGENTS.md`](../AGENTS.md) §7） |

### 三级粒度：同一事实只有一处

| 粒度 | 放在哪 | 例子（同一个工作项的三层） |
|---|---|---|
| **判据** —— 做到了没有 | `ROADMAP.md`（一句） | "移动文件夹后数据还在" |
| **手段** —— 怎么验证 | `plans/TTxx-*` | `mv` 目录 → 启动 → 断言规则仍在（附命令与预期输出） |
| **痕迹** —— 当时遇到什么 | `STATUS.md` 的已知问题 | "沙箱拒绝工作区外写入，报错像工具故障" |

### 两个自检

1. **可执行**：`just docs-check` 强制 ROADMAP 每条 ≤ 3 行、无代码块、无命令调用语法。
2. **一眼可判**：**条目数没变而文件在变长 ⇒ 细节正在泄漏。**
   「每条 ≤ 3 行」的含义正是——总量只应随**能力条目数**增长，不随细节增长。

### 为什么值得这样约束

细节**单独看每一条都"有点用"**，所以它们总能被加进来；合起来却使文件超出可读长度，
于是汇总文档不再被读 —— 而那正是它唯一的价值。**判据被掩盖时，路线图就失效了。**
